01

Predict the six-stage order

Read the documented order: PreToolUse hooks, deny rules, ask rules, permission mode, allow rules and canUseTool. Some stages resolve a call before later checks. The app shows this as reference guidance, not a fabricated SDK internal trace.

02

Observe hooks before later checks

A hook deny blocks the classroom Write even when Write is pre-approved. In a separate experiment, hook allow passes a bounded file-removal attempt onward but does not override its matching deny rule.

03

Compare deny and ask against bypass

A scoped Bash(rm *) deny blocks the attempted disposable-fixture removal in bypassPermissions. A bare Write ask rule sends a write to the host callback even in bypass mode. The callback allows only the fixed classroom output.

04

Understand callback shadowing

An allow rule or acceptEdits can approve a Write before canUseTool, so the callback count remains zero. The TypeScript SDK emits CLAUDE_SDK_CAN_USE_TOOL_SHADOWED for some configurations; acceptEdits does not trigger that construction-time warning.

05

Distinguish fallback denial from dontAsk

With default mode and no matching rule, the Write reaches a callback that denies it. In dontAsk, the unresolved Write is denied without invoking the callback. Both keep the file absent, but their traces differ.

06

Verify tool outcomes independently

Inspect actual PreToolUse and PostToolUse events, native tool results, callback invocations and host file checks. A denied tool may be followed by a successful final model response. A model statement alone does not prove that a file changed.
